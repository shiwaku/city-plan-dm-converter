# dm-converter

## 概要

DM（数値地形図データファイル）をGeoJSON形式に変換します。線・面・記号・注記の4種類に分割して出力します。

出力したGeoJSONは、QGIS等での地図表示のほか、tippecanoe・pmtiles によるベクトルタイル化を経て Web地図の背景地図として利用できます。

## 都市計画基本図とは

都市計画基本図とは、都市計画法（昭和43年法律第100号）第6条に定める「都市計画に関する基礎調査」および第14条に定める「都市計画図書」の**背景図（白図）**として使用される地形図です。

**公共測量成果**として品質を確保するため、公共測量作業規程の準則により、航空測量による新規取得・現地調査・数値図化などの作成手順と対象地物が定められています。都市計画部局が主体となって整備・更新することがほとんどで、更新頻度は5年間隔程度の場合が多いとされています。

統合型GISの普及に伴い、都市全体を網羅する都市計画基本図は地方公共団体内の共用空間データとして整備されており、都市計画部局にとどまらずハザードマップ作成など他部署での活用も増えています。また国土地理院に提出され、基盤地図情報としてとりまとめられ公開されます。

正式な規格名は**数値地図（DMデータ）**ですが、自治体によって呼称が異なります。いずれも実態は同一のデータです。

| 自治体での呼称例 | 実態 |
|---|---|
| 都市計画基本図 | 同一データ |
| 地形図 | 同一データ |
| 白図 | 同一データ |

> 出典: 国土交通省「[都市計画情報のデジタル化・オープン化ガイダンス 第1.0版 p.10](https://www.mlit.go.jp/toshi/tosiko/content/001618641.pdf#page=11)」（令和5年6月）

### 縮尺と地図情報レベル

地図情報レベルとは、国土地理院が定める数値地図の精度区分で、縮尺と対応しています。都市計画基本図では主に以下が使われます。

| 縮尺 | 地図情報レベル | 主な用途 |
|---|---|---|
| 1/25,000 | 25,000 | 都市計画基礎調査・都市計画図書の背景図 |
| 1/20,000 | 20,000 | 都市計画基礎調査・都市計画図書の背景図 |
| 1/10,000 | 10,000 | 都市計画基礎調査・都市計画図書の背景図 |
| 1/2,500 | 2,500 | 都市計画基礎調査・都市計画図書の背景図 |

> 都市計画図書のうち、総括図は25,000分の1以上、計画図は2,500分の1以上の縮尺が要件です（都市計画法第14条）。

## 対応範囲

現状では、DMデータのうち**都市計画基本図（地形図・白図）**に対応しています。

対応するレコードタイプは以下のとおりです。

| RecordType | 名称 | 対応 |
|---|---|---|
| E1 | 面 | ○ |
| E2 | 線 | ○ |
| E3 | 円 | − |
| E4 | 円弧 | − |
| E5 | 記号（点） | ○ |
| E6 | 方向 | − |
| E7 | 注記 | ○ |
| E8 | 属性 | − |

### DMデータの構造

DMファイルは固定長のレコードが並んだテキストファイル（文字コードは Shift-JIS）で、大きく2種類のレコードから構成されます。

| レコード | 役割 |
|---|---|
| 図郭レコード（`M`で始まる） | 図郭番号、図郭南西端の平面直角座標、収録要素数などの図郭単位のヘッダ |
| 要素レコード（`E`で始まる） | 個々の地物。先頭2文字がレコードタイプ（`E1`〜`E8`） |

各要素の座標は、**図郭南西端の座標（メートル）＋ センチメートル単位の相対値**として格納されています。本ツールはこれを合成して平面直角座標を復元し、EPSG:4326 へ変換します。この構造は縮尺に依存しないため、変換処理も縮尺を問いません。

線（E2）・面（E1）は座標列を6点ずつ後続レコードに格納します。始点と終点が一致する線は面として扱われるため、入力が E2 でも出力は面（`RecordType` が `E1`）になる場合があります。

```
dm-converter/
├── src/

├── package-lock.json
├── LICENSE
├── input/
│   ├── 2500/         # 縮尺1/2500のDMファイル（*.dm）を配置

```

## セットアップ

```bash
npm install
```

## 利用方法

DMファイルを `input/<縮尺>/` フォルダに配置してから実行します。

```bash
# 縮尺1/2500、座標系はデフォルト（EPSG:6676）
node src/index.js

# 縮尺1/10000
node src/index.js --scale 10000

# 縮尺1/25000（自治体によっては1/25000で整備されている）
node src/index.js --scale 25000

# 入力座標系を指定する場合
node src/index.js --epsg 6675

# 入力フォルダを直接指定する場合
node src/index.js --scale 2500 --input /path/to/dm_folder
```

よく使う2つは npm scripts でも実行できます。

```bash
npm start            # node src/index.js と同じ（1/2500）
npm run start:10000  # node src/index.js --scale 10000 と同じ
```

### オプション

| オプション | デフォルト | 説明 |
|---|---|---|
| `--scale` | `2500` | 縮尺（入力フォルダ名と出力ファイル名に使用） |
| `--epsg` | `6676` | 入力データの座標参照系（EPSGコード） |
| `--input` | `input/<scale>/` | DMファイルが格納されたフォルダ |

`--scale` は入出力パスのラベルにのみ使われ、パース処理や座標変換には影響しません。DMデータの座標は図郭南西端座標＋センチメートル単位の相対値という実座標で格納されているため、正の整数であれば任意の縮尺（1/500、1/5000、1/25000 など）を指定できます。

### 出力ファイル

`output/` フォルダに以下の4ファイルが生成されます。

| ファイル名 | 内容 |
|---|---|
| `都市計画基本図_<縮尺>_線.geojson` | 線要素（E2） |
| `都市計画基本図_<縮尺>_面.geojson` | 面要素（E1） |
| `都市計画基本図_<縮尺>_記号.geojson` | 記号・点要素（E5） |
| `都市計画基本図_<縮尺>_注記.geojson` | 注記要素（E7） |

出力されたGeoJSONはQGIS等に読み込むことで地図表示や、tippecanoe等のツールを使ってベクトルタイルへの変換が可能です。

なお、[対応範囲](#対応範囲)に記載のとおり、E3（円）・E4（円弧）・E6（方向）・E8（属性）は未対応のためスキップされます。

### 出力GeoJSONの属性

4ファイルすべてに共通する属性：

| 属性名 | 説明 | 例 |
|---|---|---|
| `Code` | 分類コード（DMの層番号） | `1106` |
| `Elno` | 要素識別番号（`図郭番号-分類コード-要素番号`） | `08ND392-1106-0001` |
| `RecordType` | レコードタイプ | `E1`（面）、`E2`（線）、`E5`（記号）、`E7`（注記） |
| `DataType` | データタイプ（日本語） | `面`、`線`、`点`、`注記` |
| `DataKind` | 実データ区分 | `0`（データなし）、`2`（二次元）、`4`（注記） |

注記（E7）のみに追加される属性：

| 属性名 | 説明 | 例 |
|---|---|---|
| `Text` | 注記文字列 | `300` |
| `Vnflag` | 縦横フラグ | `0`（横書き）、`1`（縦書き） |
| `Angle` | 文字の角度（度） | `86` |

#### `Code`（標準図式コード）について

`Code` は公共測量標準図式で定められた地物種別の識別コード（4桁数字）で、DMでは層番号として格納されています。道路・建物・植生・地形などの地物がこのコードで区別されます。

ベクトルタイル化してWeb地図で表示する際は、このコードをキーにスタイルを振り分けます。特に記号（E5）では、`Code` とスプライト（アイコン画像）を紐付けることで、公共測量標準図式に従ったシンボル表示ができます。

> 出典: 国土地理院「[作業規程の準則](https://www.gsi.go.jp/gijyutukanri/gijyutukanri41018.html)」中「[付録7 公共測量標準図式](https://www.gsi.go.jp/common/000258741.pdf)」

#### 注記の描画について

注記（E7）は代表点のポイントとして出力され、文字列は `Text`、描画向きは `Vnflag`（縦書き／横書き）と `Angle`（角度）で表現されます。測量ベンダーからGeoJSONで受領する場合は「注記_横」「注記_縦」のように縦横で別ファイルに分かれていることがありますが、本ツールは1ファイルにまとめ、`Vnflag` で区別します。スタイル設定時は `Vnflag` でフィルタしてください。

## GeoParquet変換（参考）

[OSGeo4W](https://trac.osgeo.org/osgeo4w/)のogr2ogrを使って、出力したGeoJSONをGeoParquet形式に一括変換できます。

```bat
for %f in (*.geojson) do ogr2ogr -f Parquet "%~nf.parquet" "%f"
```

## ベクトルタイル作成（参考）

出力したGeoJSONから[tippecanoe](https://github.com/felt/tippecanoe)と[pmtiles](https://github.com/protomaps/go-pmtiles)を使ってベクトルタイルを作成できます。

縮尺ごとにズーム範囲を重ならないよう割り当て、最後に `tile-join` で1ファイルに結合します。

| 縮尺 | ズーム範囲 | 最大ZL |
|---|---|---|
| 1/25,000 | Z2〜Z12 | 12 |
| 1/10,000 | Z13〜Z14 | 14 |
| 1/2,500 | Z15〜Z16 | 16 |

### 最大ズームレベルの決め方

ベクトルタイルは座標をタイル内の整数格子（0〜4,095）に量子化して格納するため、変換時にわずかな位置誤差が生じます。元データの精度を損なわないよう、**格子間隔（分解能）が地図の許容誤差以下**になる最小のZLを最大ズームレベルに選びます。

- **許容誤差** = 縮尺分母 × 0.1mm（図上0.1mmに相当する地上距離）
- **分解能** = 赤道周長 40,075,016.686m ÷ (2^ZL × 4,096)

| 縮尺 | 許容誤差 | 最大ZL | そのZLの分解能 | 1段下のZLの分解能 |
|---|---|---|---|---|
| 1/25,000 | 2.5m | **12** | 2.389m | 4.777m ✗ |
| 1/20,000 | 2.0m | **13** | 1.194m | 2.389m ✗ |
| 1/10,000 | 1.0m | **14** | 0.597m | 1.194m ✗ |
| 1/5,000 | 0.5m | **15** | 0.299m | 0.597m ✗ |
| 1/2,500 | 0.25m | **16** | 0.149m | 0.299m ✗ |

分解能は赤道基準の最大値で、実際には緯度 φ において cos φ 倍に小さくなります（静岡市付近の北緯35度では ZL16 で約0.12m）。したがって上表のZLであれば日本国内では余裕をもって許容誤差を満たします。

### tippecanoe のオプション

| オプション | 意味 |
|---|---|
| `-Z` / `-z` | 最小／最大ズームレベル |
| `-r1` | ポイントの間引きを無効化。**記号・注記では必須**（付けないと点が間引かれて消える） |
| `--no-feature-limit` | タイルあたりのフィーチャ数上限を解除 |
| `--no-tile-size-limit` | タイルサイズ上限を解除 |
| `-L` | レイヤー名を指定して入力ファイルを追加 |
| `--force` | 既存の出力ファイルを上書き |

密集地物でタイルサイズが問題になる場合は `--drop-densest-as-needed` の併用を検討してください。

### 1/2500 → MBTiles

```bash
tippecanoe \
  -o kihonzu_2500.mbtiles \
  -Z15 -z16 \
  -r1 \
  --no-feature-limit \
  --no-tile-size-limit \
  --force \
  -L kihonzu_2500_line:都市計画基本図_2500_線.geojson \
  -L kihonzu_2500_polygon:都市計画基本図_2500_面.geojson \
  -L kihonzu_2500_symbol:都市計画基本図_2500_記号.geojson \
  -L kihonzu_2500_annotation:都市計画基本図_2500_注記.geojson
```

### 1/10000 → MBTiles

### 結合・PMTiles変換

```bash
# 各縮尺を1ファイルに結合（整備されている縮尺のみ指定すればよい）
tile-join \
  -o kihonzu.mbtiles \
  --force \
  --no-tile-size-limit \
  kihonzu_25000.mbtiles \
  kihonzu_10000.mbtiles \
  kihonzu_2500.mbtiles

# PMTilesに変換
pmtiles convert kihonzu.mbtiles kihonzu.pmtiles
pmtiles convert kihonzu_25000.mbtiles kihonzu_25000.pmtiles
pmtiles convert kihonzu_10000.mbtiles kihonzu_10000.pmtiles
pmtiles convert kihonzu_2500.mbtiles kihonzu_2500.pmtiles
```

## 利用上の注意

DMデータは測量法に基づく**公共測量成果**です。公共測量成果を複製または使用する場合は、原則として測量法第29条（複製の承認）・第30条（使用の承認）に基づき、測量成果を保有する測量計画機関の長の承認が必要です。

上記「データ出典」の静岡市 都市計画基本図については、静岡市において使用承認を得たうえでオープンデータとして公開されています。利用にあたっては配布元の利用規約を確認してください。

他自治体のDMデータを変換して利用する場合は、当該自治体が定める複製・使用の手続きおよび利用条件に従ってください。本ツールのライセンス（MIT）が対象とするのは変換プログラムであり、入力するDMデータおよび変換結果の利用条件はこれとは別に定まります。
